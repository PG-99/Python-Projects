# 100 Python Projects: Beginner to Advanced

This repository is a learning and portfolio roadmap for someone starting Python from zero. It contains 100 projects arranged in the order you should build them. Every project includes its purpose, the Python ideas you will practice, a suggested file structure, coding steps, an explanation of the program's data flow, tests, and a portfolio upgrade.

This is deliberately a build guide, not a collection of finished answers. Writing the code yourself, committing your progress, and being able to explain your choices will add far more credibility than uploading 100 copied solutions.

## Start here

1. Read [Getting Started](GETTING_STARTED.md).
2. Follow the [12-week starter plan](STARTER_PLAN.md) if you want a manageable schedule.
3. Copy [the project README template](templates/PROJECT_README_TEMPLATE.md) into each new project.
4. Build the levels in order. It is fine to skip a project that repeats a skill you already know.
5. Publish one project at a time, with tests, screenshots, and an honest README.

## The roadmap

| Level | Projects | Main outcome |
|---|---:|---|
| [1 — Foundations](roadmap/level-1-foundations.md) | 1–20 | Variables, functions, loops, files, errors, and small command-line programs |
| [2 — Practical Python](roadmap/level-2-practical.md) | 21–40 | OOP, SQLite, APIs, automation, desktop interfaces, and safer file tools |
| [3 — Web and Data](roadmap/level-3-web-data.md) | 41–60 | Web apps, REST APIs, data analysis, machine learning, async code, and scraping |
| [4 — Production Systems](roadmap/level-4-production.md) | 61–80 | Architecture, caching, queues, ETL, real-time systems, ML serving, and monitoring |
| [5 — Advanced Engineering](roadmap/level-5-advanced.md) | 81–100 | Packages, language tools, networking, distributed systems, security, and a capstone |

## A realistic pace

- Projects 1–20: 2–6 hours each.
- Projects 21–40: 1–3 days each.
- Projects 41–60: 3–7 days each.
- Projects 61–80: 1–3 weeks each.
- Projects 81–100: 2–6 weeks each.

Do not measure success by reaching project 100 quickly. Ten well-explained repositories are stronger than 100 empty or copied ones. A good early target is projects 1–10, then one polished project from each later level.

## Recommended repository strategy

Use this roadmap as one repository. Give larger portfolio projects their own repositories. For example:

```text
python-100-projects/       # notes and small projects 1–20
expense-tracker/           # polished standalone project
fastapi-task-api/          # polished standalone project
document-search-engine/    # polished standalone project
developer-platform/        # final capstone
```

Pin your best 4–6 repositories on your GitHub profile. Each pinned project should have a clear README, installation steps, screenshots or a short demo, tests, meaningful commits, and a license.

## What “finished” means

A project is finished when another person can clone it, follow the README, run it, and understand what you learned. Use [the portfolio checklist](templates/PORTFOLIO_CHECKLIST.md) before publishing.

## A note about GitHub credibility

Green contribution squares and a large repository count are weak signals by themselves. Stronger evidence is a small set of projects with clear decisions, tests, readable commits, a demo, and visible improvement over time. Never hide tutorial origins: credit the source, describe what you changed, and be ready to explain the code.
