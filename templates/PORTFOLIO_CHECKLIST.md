# Portfolio Project Checklist

## Code

- [ ] I can explain every important line and dependency.
- [ ] Functions and variables have descriptive names.
- [ ] Core logic is separated from input/output and storage.
- [ ] Invalid input and expected failures are handled.
- [ ] There are no passwords, keys, personal records, or generated junk files.
- [ ] Dependencies are pinned and unused packages are removed.

## Tests and quality

- [ ] Tests cover normal, boundary, and invalid cases.
- [ ] `python -m pytest` passes from a fresh environment.
- [ ] Formatting and lint checks pass when configured.
- [ ] A new clone works by following only the README.

## GitHub presentation

- [ ] The repository has a useful name, description, and accurate topics.
- [ ] The README leads with the result, not a diary of the build.
- [ ] Setup and usage commands are copyable.
- [ ] Screenshots, sample output, or a short demo are included.
- [ ] Commit messages describe meaningful steps.
- [ ] The repository has a license and no large generated files.
- [ ] The strongest technical decision and tradeoff are explained.

## Credibility

- [ ] I changed the project beyond the tutorial specification.
- [ ] I can give a two-minute explanation without reading notes.
- [ ] I can describe one bug I found and how I diagnosed it.
- [ ] Issues or a roadmap show thoughtful next steps.
- [ ] The default branch is green in continuous integration for larger projects.
